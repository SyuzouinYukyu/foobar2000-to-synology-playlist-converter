1. FTSPCとは

FTSPC（foobar2000 to Synology Playlist Converter）は、 Windows上のfoobar2000で使用しているM3U/M3U8プレイリストのパスを、 Synology NAS上のメディアサーバーから参照しやすい形式へ変換するWindows GUIツールです。 逆に、NAS用プレイリストをWindows用へ戻すこともできます。

Windows → NAS

G:\AMZN_01\Jazz\... のようなWindowsパスを、NAS側で使えるパスへ変換します。

NAS → Windows

NAS絶対パスや、プレイリスト保存先を基準にした相対パスを解決してWindowsパスへ戻します。

安全設計

音源ファイルそのものを移動・改名・削除しません。プレイリストは別ファイルとして出力し、保存は原子的に行います。

複数一括

複数プレイリストの一括診断・一括変換に対応し、正常なファイルと要確認ファイルが混在しても個別に処理できます。

FTSPCはNASの共有フォルダー構造を変更するソフトではありません。 M3Uの中に「どのパス表記を書くか」を変換するソフトです。 通常運用ではSSHやbind mountを必要としません。

v1.2.3で追加・改善された点

  • 長時間処理中の進捗表示を改善（処理内容、件数、割合、経過時間。総数不明時はMarquee）。
  • キャンセル操作中に「キャンセルしています...」表示が別の進捗通知で上書きされないよう改善。
  • 専用ドロップ領域を廃止し、メインGUI全域で .m3u / .m3u8 の複数D&Dに対応。
  • 非対応ファイルやフォルダーだけをD&Dした場合、日本語で理由を案内。
  • パスペア設定の「逆変換で優先」を、より分かりやすい 「NAS→Windows変換時、このWindowsパスを優先」へ変更。

2-2. Microsoft Defender SmartScreenが表示された場合

v1.2.3はコード署名されていないため、GitHubからダウンロードした正式EXEでも 「WindowsによってPCが保護されました」と表示される場合があります。

先にSHA-256を確認してください。 正式GitHub Releaseから取得したファイルで、下記のSHA-256と一致することを確認してから実行してください。 身元不明の転載サイトや第三者配布ファイルでは、この手順での実行を推奨しません。 
Get-FileHash -Algorithm SHA256 .\FTSPC_v1.2.3.exe

期待値：

60D319078E87DB4179C93EB86CFF17EA9D19287D4E796C023ECA831F2662370F

一致していることを確認できた場合、SmartScreen画面の［詳細情報］から実行できます。

2-3. 内蔵自己テスト（任意）

FTSPCには --self-test が組み込まれています。 GUIアプリなので、PowerShellから直接実行すると標準出力が見えないことがあります。 確実に確認するには次の方法を使います。 

$Out = Join-Path $PWD 'selftest_stdout.txt'
$Err = Join-Path $PWD 'selftest_stderr.txt'

Remove-Item $Out,$Err -ErrorAction SilentlyContinue

$p = Start-Process `
    -FilePath '.\FTSPC_v1.2.3.exe' `
    -ArgumentList '--self-test' `
    -Wait `
    -PassThru `
    -RedirectStandardOutput $Out `
    -RedirectStandardError $Err

Write-Host "ExitCode =" $p.ExitCode
Get-Content $Out
Write-Host "stderr size =" (Get-Item $Err).Length "bytes"
合格の目安： ExitCode = 0、 SELF_TEST_GROUPS_OK: passed=19 failed=0、 SELF_TEST_OK、 stderr size = 0 bytes。 日本語ログが文字化けしても、これらの英数字の判定行が読めれば合否確認には支障ありません。

3. メイン画面の見方

FTSPC v1.2.3 メイン画面。画面サイズやフォント設定によって見え方は多少変わります。

① プレイリスト

  • ［ファイルを追加］：M3U/M3U8を選択して追加。
  • ［選択を削除］：一覧で選択したプレイリストを一覧から外します。元ファイル自体は削除しません。
  • ［すべて削除］：登録一覧を空にします。元ファイル自体は削除しません。
  • 一覧：プレイリスト名、曲数、推奨NAS保存先、状態を表示します。
v1.2.3： M3U/M3U8は、特定の専用枠だけでなくメインGUIの広い範囲へドラッグ＆ドロップできます。 複数ファイルの同時追加にも対応します。

非対応ファイル・フォルダー・存在しない項目だけをドロップした場合は、 「追加できるプレイリストがありません。.m3u または .m3u8 ファイルを選んでください。フォルダーや存在しない項目は追加できません。」 という趣旨の案内が表示されます。

② 変換前診断

プレイリストを追加すると自動診断されます。 設定を変更した後は［診断を更新］で診断し直します。 この領域で、変換可能か、マッピング不能や設定競合がないか、生成例が意図どおりかを確認します。

③ 出力・変換

  • PC上の出力先：変換後ファイルをWindowsから保存する場所。
  • 方向：Windows→NAS、NAS→Windowsを選択。
  • ［変換する］：変換開始。
  • ［キャンセル］：長時間処理中のキャンセル。
  • ［詳細設定］：文字コード、安全設定、レポートなどを変更。
  • 表示 pt：9～17ptの範囲で表示サイズを調整。

4. 初見でつまずきやすい「3つの重要用語」

4-1. パスペア（PathPair）

同じ音源がWindows側とNAS側で「どこにあるか」を対応付ける設定です。 

Windows側: G:\AMZN_01\Jazz\
NAS側    : /volume1/AMZN_01/Jazz/

FTSPCはこの対応関係を使い、WindowsパスをNASの実体パスへ変換します。 逆変換ではNAS側からWindows側へ戻します。

4-2. プレイリスト保存先（PlaylistDestination）

M3UをNAS内部のどこに置くかを表します。 Windowsから見たUNCパスと、NAS内部パスは表記が異なりますが、 同じ実フォルダーを指すように設定します。 

Windowsから見た保存先 : \\DS224\wd80eazz\Playlist
NAS内部での保存先     : /volume2/WD80EAZZ/Playlist/

4-3. この保存先から見える音源（VisibilityRule / 参照ルール）

NASの実体パスを、M3U内ではどの文字列で書けばメディアサーバーから参照できるかを指定します。

M3U出力パス接頭辞意味
/ から始まるNAS絶対パスとして出力。
/ 以外で始まるプレイリスト保存先を基準とする相対パス。
../ を含む上位フォルダーへ遡る相対パス。FTSPCは安全性を確認しながら扱います。
参照ルールはNAS側にフォルダーやマウントを作成する設定ではありません。 M3Uに書くパス表記だけを決める設定です。

5. 初回設定

5-1. パスペアを設定する

  1. メイン画面の［パスペア設定を開く］を押します。
  2. ［＋ ペアを追加］。
  3. 分かりやすい表示名を付けます（例：Jazz、Classic、AMZN_01）。
  4. 「Windows側パス」と「NAS側パス」を入力します。
  5. 同じNAS領域にWindows候補が複数ある場合、必要なペアで ［NAS→Windows変換時、このWindowsパスを優先］をONにします。
  6. 設定を反映します。
前後に対応する半角ダブルクォート "..." が付いたパスを貼り付けても正規化されます。 UNCパスも利用できます。

5-2. プレイリスト保存先を設定する

  1. ［プレイリスト保存先設定を開く］。
  2. ［＋ 保存先を追加］。
  3. 表示名を入力（例：WD80EAZZ Playlist）。
  4. 「NAS上のプレイリスト保存先」にNAS内部パスを入力。
  5. 通常使う保存先なら［優先保存先］をON。
  6. 詳細画面で参照ルールを設定します。

5-3. 「この保存先から見える音源」を設定する

項目入力する内容
実際のNAS音源ルート音源の本当のNAS内部パス。例：/volume1/AMZN_01/
M3U出力パス接頭辞その音源をM3Uへ書くときの先頭部分。絶対パス・相対パスのどちらも可。
実体と一致しない ../ を無理に設定しないでください。 参照先の考え方が誤っていると、設定競合・変換不可・メディアサーバー側で空表示、などの原因になります。

5-4. PC上の出力先を設定する

メイン画面「③ 出力・変換」の「PC上の出力先」へ、Windowsから書き込めるフォルダーを指定します。 NASへ直接保存する場合はUNCパスを使えます。 

例: \\DS224\wd80eazz\Playlist

「PC上の出力先」と「NAS上のプレイリスト保存先」は、 表記方法が違っても同じ実フォルダーを指すようにします。

6. Windows → NAS用へ変換

6-1. プレイリストを追加

［ファイルを追加］またはドラッグ＆ドロップで .m3u / .m3u8 を追加します。 複数ファイルをまとめて追加できます。

6-2. 変換前診断を読む

代表的な正常イメージ：

曲数: 15
✓ 変換可能
プレイリスト保存先: WD80EAZZ Playlist
NASへ配置する場所: /volume2/WD80EAZZ/Playlist/
マッピング不能: 0
設定競合: 0

「生成例」が表示される場合は、実際にM3Uへ書かれるパスが意図どおりか確認してください。

6-3. 変換する

  1. 変換したい行を選択。複数行選択可。
  2. 方向を［Windows → NAS用へ変換］にします。
  3. PC上の出力先を確認。
  4. ［変換する］。
  5. 完了後、出力ファイルを確認。
入力標準の出力名Auto時の標準文字コード
playlist.m3uplaylist_Synology.m3uUTF-8（BOMなし）
playlist.m3u8playlist_Synology.m3u8UTF-8（BOMなし）

出力はCRLF、先頭は #EXTM3U に統一され、NAS側では / 区切りを使用します。 コメント/メタデータ、曲順、重複エントリは変換側で保持されます。

6-4. v1.2.3の進捗表示

処理中は「③ 出力・変換」付近に進捗が表示されます。 総数が分かる処理では現在件数・総件数・割合・経過時間が表示されます。 総数を事前に確定できない処理ではMarquee表示になります。

キャンセル操作を行うと「キャンセルしています...」の状態を保ち、 遅れて到着した進捗通知に表示が戻らないようv1.2.3で改善されています。

6-5. 同名ファイルがある場合

［上書き保存］［保存しない］［別名で保存］を選べます。 複数ファイルの一括処理中は［全て上書き保存］も利用できます。 「全て上書き」はそのバッチ処理だけに適用され、次回処理には持ち越されません。

7. 複数プレイリストを一括変換

プレイリスト一覧で複数行を選択し、そのまま［診断を更新］または［変換する］を使います。 正常なプレイリストと「要確認」があるプレイリストが混在しても、各ファイル単位で処理されます。

大量処理の前に、10～20曲程度の小さなテストプレイリストで主要な音源領域を1～2曲ずつ確認しておくと、 設定ミスを早く見つけられます。

v1.2.3では長時間処理の進捗が見やすくなっているため、複数一括変換時も現在位置を把握しやすくなっています。

8. 変換できない曲があるとき — 強制変換

パスペアがない音源、候補を一意に決められない曲、意図的にNAS対象外にした曲などが含まれる場合、 通常変換では確認が必要になります。そこで使えるのが強制変換です。

強制変換の動作

  • 変換可能な曲だけで新しいプレイリストを作成。
  • 変換できない曲は行単位でスキップ。
  • 元のプレイリストは変更しない。
  • 残った曲の元の順序を維持。
  • 重大なI/Oエラーなどを単純な「スキップ」で隠さない。
  • 変換可能曲が0曲なら強制変換しない。
「マッピング不能」が大量に出る場合は、強制変換で回避するより、 まずパスペア設定を見直すのが本来の解決です。 強制変換は「対象外曲を意図的に落としてプレイリストを作る」場合に使います。

9. NAS → Windows用へ逆変換

変換方向を［NAS → Windows用へ逆変換］へ切り替えて使います。

9-1. 解決できる代表的なNAS側パス

  • /volumeUSB1/... のようなNAS絶対パス。
  • Music/... のような保存先基準の相対パス。
  • ../../../volume1/... のような上位相対パス。

まずNAS上の実体パスへ正規化し、その後パスペアを使ってWindowsパスへ戻します。 同じNASルートにWindows候補が複数ある場合は、 「NAS→Windows変換時、このWindowsパスを優先」が選択に使われます。

項目標準
出力名元名_Windows.m3u / .m3u8
Auto時文字コードShift_JIS / CP932
パス区切り\
CP932で表現できない文字がある場合、標準の安全設定ではその行をコメントアウトして要確認にできます。 互換性優先で置換して継続する設定もあります。

表示サイズ

メイン画面の「表示 pt」で9～17ptに変更できます。

  • Ctrl + +：拡大
  • Ctrl + -：縮小
  • Ctrl + 0：14ptへ戻す
  • テンキーの + / - にも対応

「② 変換前診断」と下部領域の境界はドラッグで高さを変更でき、その位置も保存されます。

自動修復の安全設計

フォルダー改名の推定は、正規化後のファイル名と拡張子が一致する曲を根拠にします。 トラック番号だけの一致では修復しません。

フォルダー対応は、最低3曲・80%以上・候補一意・競合なしの場合だけ登録します。 アクセス拒否、I/O障害、UNC/NAS切断、キャンセル等で走査が完了しなかったルートの索引は破棄し、 そのルートでは自動修復を行いません。

  • AMZN_01の上位相対パスを正常認識。
  • AMZN_02 / AMZN_03のNAS絶対パスを正常認識。
  • 相対パスと絶対パスを同一M3U内に混在可能。
  • bind mountなしで再生確認。
  • 曲順・重複エントリはFTSPC側で保持。
同一曲を重複登録した場合、FTSPCは重複を保持しますが、 メディアサーバー/コントローラー側が同一URIを1項目として扱うことがあります。

14. トラブルシューティング

Q. プレイリスト名は見えるのに、中身が空になる

最優先で「生成例」と参照ルールを確認してください。 M3U自体が見えていても、曲のパスをメディアサーバーが解決できなければ中身は空になります。 「NAS上のプレイリスト保存先」と「M3U出力パス接頭辞」の組み合わせが重要です。

Q. Windows上では存在するのに「マッピング不能」になる

そのWindowsパスに対応するパスペアがありません。 ［パスペア設定を開く］で、Windows側ルート ↔ NAS側実体ルートを追加してください。

Q. 「候補が複数」が出る

複数のパスペアや修復候補が同程度に一致しています。 重複設定を整理してください。 NAS→Windows逆変換で複数Windows候補が必要な場合は、 適切なペアに［NAS→Windows変換時、このWindowsパスを優先］を設定します。

Q. フォルダーをドラッグしても追加されない

FTSPC v1.2.3のD&D対象は .m3u / .m3u8 ファイルです。 フォルダーや存在しない項目は追加対象ではありません。

Q. 同じ曲を2回入れたのに、再生側では1曲少ない

FTSPCはM3U内の重複を保持します。 一方、Synology Media Serverや再生コントローラー側が同一URIを1項目へまとめる場合があります。 FTSPCが重複を削除したとは限りません。

Q. 変換中にキャンセルすると出力ファイルが壊れない？

出力は一時ファイルへ書き、完了後に最終ファイルへ移動する原子的な保存方式です。 キャンセル時は、未確定の一時ファイルを残さない設計です。 v1.2.3ではキャンセル中表示も安定するよう改善されています。

Q. SSHやbind mountは必要？

通常運用では不要です。 参照ルールで安全な相対パスとNAS絶対パスを使い分けられるため、 実機確認済み構成ではbind mountなしで動作しています。

Q. いきなり大量のプレイリストを変換してもよい？

設定直後は小さなテストプレイリストで主要音源領域を確認することを推奨します。 正常確認後に複数一括へ進む方が、設定ミスの切り分けが容易です。

Q. SmartScreenが出た。危険なファイル？

コード署名がないため、正式配布EXEでもSmartScreenが出る場合があります。 必ずGitHubの正式Releaseから取得し、SHA-256が本書記載値と一致することを確認してください。

Q. --self-testの結果がPowerShellに何も出ない

GUI形式のEXEなので、直接実行では標準出力や終了コードが見えない場合があります。 本書「2-3. 内蔵自己テスト」の Start-Process 手順で標準出力・標準エラー・ExitCodeを明示的に取得してください。

15. 安全に使うための注意点

  • 音源ファイル本体は移動・改名・削除しません。
  • 初回設定後は、小さなプレイリストで出力内容と実再生を確認してから本運用へ進んでください。
  • 既存の重要なプレイリストはバックアップしておくと安心です。
  • 「マッピング不能」が大量に出た場合は、強制変換より先に設定を見直してください。
  • ログを外部へ共有する場合、個人情報、NAS名、非公開パス、IPアドレス、資格情報などを伏せてください。
  • 設定を大きく変更する前に、設定エクスポートを推奨します。
FTSPCはパス変換の補助ツールです。 NAS側のアクセス権、共有フォルダー設定、メディアサーバーのライブラリ範囲、ネットワーク接続などが誤っている場合、 FTSPCだけでは解決できません。

16. Synology以外のNASについて

FTSPCの基本原理は「Windows側パスとNAS側パスを対応付け、M3Uへ適切なパス表記を書き出す」ことです。 そのため、理論上はSynology以外のNASや自作メディアサーバーでも、 そのサーバーが理解できるM3Uパス形式をFTSPCの設定で再現できれば利用できる可能性があります。

ただし、正式な実機確認はSynology環境を中心に行われています。 QNAP、ASUSTOR、TrueNAS、OpenMediaVault、Unraidなどでの動作を本書は保証しません。 他環境で使う場合は、小規模テストと実再生確認を必ず行ってください。
