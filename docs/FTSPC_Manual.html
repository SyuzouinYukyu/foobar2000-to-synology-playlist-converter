1. このソフトは何をする？

foobar2000 to Synology Playlist Converter（以下 FTSPC）は、Windows上の foobar2000 で使っている .m3u / .m3u8 プレイリスト内のパスを、Synology NAS上で読める形へ変換するWindowsアプリです。逆に、NAS用プレイリストをWindows用へ戻すこともできます。

Windows → NAS
G:\AMZN_01\Jazz\... のようなWindowsパスを、NASの実体に対応するM3Uパスへ変換します。
NAS → Windows
NAS絶対パスや、プレイリスト保存先からの相対パスを解決してWindowsパスへ戻します。
安全設計
元のプレイリストは変更せず、別名の新しいプレイリストを作成します。出力は一時ファイル経由のatomic saveです。
複数一括
複数のプレイリストを同時に診断・変換できます。正常なものと強制変換が必要なものが混在しても個別に処理されます。
通常の使い方ではSSHもbind mountも不要です。 FTSPCはNASの構成そのものを変更するソフトではありません。M3Uに書く「見え方」を設定して変換します。

3. 初見でつまずきやすい「3つの重要用語」

① パスペア

同じ音源が、WindowsとNASで「どこにあるか」を対応付ける設定です。

Windows側パス                     NAS側パス
G:\AMZN_01\Jazz\        ↔        /volume1/AMZN_01/Jazz/

FTSPCはこの対応関係を使って、WindowsのパスをNASの実体パスへ変換します。

② プレイリスト保存先

M3UをNAS内部のどこに置くかを表します。Windowsから保存するUNCパスとは表記が違いますが、同じ実フォルダを指すように設定します。

Windowsから見た保存先 : \\DS224\wd80eazz\Playlist
NAS内部での保存先     : /volume2/WD80EAZZ/Playlist/

③ この保存先から見える音源（参照ルール）

NASの実体パスを、M3U内ではどの文字列で書けばSynology Media Serverから見えるかを指定します。

M3U出力パス接頭辞意味
/ から始まるNAS絶対パスとして出力
/ 以外で始まるプレイリスト保存先を基準とする相対パス
../ を含む上位フォルダへ遡る相対パス。v1.2.2では実体パスが一致する場合だけ安全に使用
重要： 参照ルールはNASにフォルダやマウントを作る設定ではありません。「M3Uの中にどのパスを書くか」だけを決めます。

4. 初回設定

4-1. パスペアを設定する

  1. メイン画面の［パスペア設定を開く］を押します。
  2. ［＋ ペアを追加］。
  3. 分かりやすい表示名を付けます（例：Jazz、Classic、邦楽）。
  4. 「Windows側パス」と「NAS側パス」を入力します。
  5. NAS→Windows逆変換で同じNAS領域に複数のWindows候補がある場合、必要に応じて［逆変換で優先］を指定します。
  6. ［設定を反映］。
パス欄は、前後の対応する半角ダブルクォート "..." が貼り付いていても正規化されます。UNCパスも保持されます。

4-2. プレイリスト保存先を設定する

  1. ［プレイリスト保存先設定を開く］。
  2. ［＋ 保存先を追加］。
  3. 表示名（例：WD80EAZZ Playlist）を入力。
  4. 「NAS上のプレイリスト保存先」にNAS内部パスを入力します。
  5. 通常使う保存先なら［優先保存先］をON。
  6. ［詳細］を押して参照ルールへ進みます。

4-3. 「この保存先から見える音源」を設定する

v1.2.2で特に重要な画面です。各ルールには次の2項目があります。

項目入力する内容
実際のNAS音源ルート音源の本当のNAS内部パス。例：/volume1/AMZN_01/
M3U出力パス接頭辞その音源をM3Uへ書くときの先頭部分。絶対パスでも相対パスでも可
実体と一致しない ../ を無理に設定しないでください。 v1.2.2は実体一致を検証します。正しくないルールは「設定競合」「変換不可」などの原因になります。

4-4. PC上の出力先を設定する

メイン画面「③ 出力・変換」の「PC上の出力先」へ、Windowsから書き込めるフォルダを指定します。NASへ直接保存する場合はUNCパスを使えます。

例：\\DS224\wd80eazz\Playlist
「PC上の出力先」と「NAS上のプレイリスト保存先」は、表記方法は違っても同じ実フォルダを指すようにします。

5. Windows → NAS用へ変換

5-1. プレイリストを追加

［ファイルを追加］またはドラッグ＆ドロップで .m3u / .m3u8 を追加します。複数選択できます。

一覧には「プレイリスト名」「曲数」「推奨NAS保存先」「状態」が表示されます。

5-2. 変換前診断を読む

追加すると自動診断されます。代表的な正常例：

曲数: 15
✓ 変換可能
プレイリスト保存先: WD80EAZZ Playlist
NASへ配置する場所: /volume2/WD80EAZZ/Playlist/
マッピング不能: 0 / 設定競合: 0

「生成例」には、実際にM3Uへ書かれるパスが表示されます。ここを見れば、参照ルールが意図どおりか事前に確認できます。

5-3. 変換する

  1. 変換したい行を選択します。複数行選択可。
  2. 方向を［Windows → NAS用へ変換］にします。
  3. ［変換する］。
  4. 出力ファイルを確認します。
入力標準の出力名標準の文字コード
playlist.m3uplaylist_Synology.m3uUTF-8 BOMなし
playlist.m3u8playlist_Synology.m3u8UTF-8 BOMなし

#EXTM3U は出力先頭に1行へ統一され、コメント/メタデータ行は保持されます。曲順と重複エントリも変換側では保持されます。

5-4. 同名ファイルがすでにある場合

［上書き保存］［保存しない］［別名で保存］を選べます。複数ファイルの一括処理中は［全て上書き保存］も選択できます。

［全て上書き保存］の状態はそのバッチ処理だけで有効です。次の変換ではリセットされます。

6. 複数プレイリストを一括変換

プレイリスト一覧で複数行を選択し、そのまま［診断を更新］または［変換する］を使います。

7. 変換できない曲があるとき — 強制変換

パスペアがない音源や、候補を一意に決められない曲が含まれる場合、通常変換では確認が必要になります。そこで使えるのが強制変換です。

強制変換の動作

  • 変換可能な曲だけで新しいプレイリストを作成
  • 変換できない曲は行単位でスキップ
  • 元のプレイリストは変更しない
  • 曲順は残った曲の元順序を維持
  • 重大なI/Oエラーなどを「スキップ扱い」で隠さない
  • 変換可能曲が0曲なら強制変換できない

誤操作防止のため、実行は2段階確認です。最初に「変換できない曲があります」、次に「強制変換の最終確認」が表示されます。

「マッピング不能」が大量にある場合は、先にパスペア設定を追加するのが本来の解決です。強制変換は「NASに存在しない/対象外の音源を意図的に除外して作りたい」ときに使います。

8. NAS → Windows用へ逆変換

方向を［NAS → Windows用へ逆変換］へ切り替えて使います。

v1.2.2が解決できるNAS側パス

  • /volumeUSB1/... のようなNAS絶対パス
  • Music/... のような保存先基準の相対パス
  • ../../../volume1/... のような安全な上位相対パス

まずNAS上の実体パスへ正規化し、その後パスペアを使ってWindowsパスへ戻します。同じNASルートにWindows候補が複数ある場合は「逆変換で優先」が選択に使われます。

標準出力名Auto時の標準文字コード
元名_Windows.m3u / .m3u8Shift_JIS / CP932
CP932で表現できない文字がある場合、標準設定ではその行をコメントアウトして要確認にします。「詳細設定」で置換して継続する方式にも変更できます。

12. トラブルシューティング

Q. BubbleUPnPにプレイリスト名は出るのに「This folder is empty.」になる

最優先で「生成例」と参照ルールを確認してください。M3U自体が見えていても、曲のパスをSynology Media Serverが解決できないと中身が空になります。プレイリスト保存先と、M3U出力パス接頭辞の組み合わせが重要です。

Q. Windows上では存在するのに「マッピング不能」になる

そのWindowsパスに対応する「パスペア」がありません。［パスペア設定を開く］で、Windows側ルート ↔ NAS側実体ルートを追加してください。

Q. 「候補が複数」が出る

複数のパスペアや修復候補が同程度に一致しています。重複設定を整理するか、NAS→Windows逆変換なら適切なパスペアへ［逆変換で優先］を付けます。

Q. 同じ曲を2回入れたのにBubbleUPnPでは1曲少ない

FTSPCはM3U内の重複を保持します。ただしSynology Media Server / BubbleUPnP側が同一URIを1項目へまとめる場合があります。実機では15エントリ（同一曲1件重複）が14 tracksとして表示されました。これはFTSPCが重複を削除した結果ではありません。

Q. 変換中にキャンセルしたら出力ファイルが壊れない？

出力は一時ファイルに書き、完了後に最終ファイルへ移動するatomic saveです。キャンセル時は保存済みファイルを維持し、未確定の一時ファイルを削除する設計です。

Q. SSHやNASのbind mountは必要？

通常運用では不要です。v1.2.2は参照ルールで安全な ../ 相対パスとNAS絶対パスを混在できるため、実機構成ではbind mountなしで再生確認済みです。

Q. いきなり大量のプレイリストを変換してもよい？

設定直後は10～20曲程度の小さなテストプレイリストで、AMZN_01/02/03など主要領域を1～2曲ずつ含めて確認するのがおすすめです。正常確認後に複数一括へ進むと切り分けが容易です。
